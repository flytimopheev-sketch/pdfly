# pdfly 0.2.1

Заполненные статические XFA-формы и перенос таблиц по страницам.

## Что нового

- Значения из сохранённого пакета XFA `datasets` связываются с простыми
  полями `dataRef` перед отрисовкой. Привязка выполняется только в памяти,
  исходный PDF не изменяется.
- Строки повторяющихся таблиц получают высоту по содержимому, разбиваются
  между страницами, а заголовок таблицы повторяется на каждой странице.
- Блок подписей переносится на отдельную страницу; расположенный после него
  блок даты больше не накладывается на таблицу.
- Исправлен порядок элементов при замене таблицы: `pageSet` остаётся перед
  таблицей, поэтому разрыв страницы не срабатывает до создания страниц.
- Добавлена фикстура `bound-xfa.pdf` и offscreen-проверки привязки данных,
  разбиения таблицы, порядка элементов и рендеринга.
- Неподдерживаемые или повреждённые XFA-формы по-прежнему открываются как
  исходный документ без изменения файла на диске.

## Установка

```bash
sudo dnf install ./pdfly-0.2.1-1.red80.x86_64.rpm
pdfly --version
pdfly
```

Пакет собран для RedOS 8 x86_64. PDF4QT Core 1.6.0.0 поставляется внутри
RPM в `/usr/lib64/pdfly`, поэтому отдельная установка PDF4QT не требуется.

## Проверено

- RedOS 8 x86_64, GCC 13.3.1, Qt 6.9.3, CUPS 2.4.20.
- PDF4QT Core 1.6.0.0, commit `67b6b99`.
- Offscreen smoke-тесты: обычный PDF, статическая XFA, привязка `datasets`,
  разбиение повторяющейся таблицы, flatten и CUPS direct/flatten/multi.
- Две реальные формы Adobe LiveCycle Designer: значения полей, перенос
  таблиц с повтором заголовков, блоки подписей и дат отображаются на
  отдельных страницах.

## Ограничения

pdfly — просмотрщик только для чтения. Поддерживается практический subset
статического XFA: простые `dataRef`, повторяющиеся строки таблиц и перенос
блока подписей. Динамический XFA, JavaScript, FormCalc, произвольный
XFA-layout и редактирование полей не поддерживаются. PDF4QT разбирает
только статический `template`; подробнее — в
[README](https://github.com/flytimopheev-sketch/pdfly#xfa-что-поддерживается).
